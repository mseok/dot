# Browser use in Codex desktop

Preference recorded 2026-10-11 and moved out of AGENTS.md on 2026-10-17; the one-line rule in AGENTS.md points here.

- Default to the built-in Browser (`@Browser`) for local and external websites. Do not require the user to name it each time. Keep it in the background unless the user is watching or recording; then make the tab visible. Direct file parsing, connected APIs and ordinary web search remain appropriate for tasks that do not need a browser UI.
- Use the installed Browser plugin's trusted Node REPL runtime. Read its skill, discover browsers with `agent.browsers.list()`, select type `iab`, and read `browser.documentation()` before interacting. If the skill is absent from the session, check the installed plugin's packaged bootstrap documentation and public `setupBrowserRuntime` entrypoint before declaring the Browser unavailable; discover the current installation path instead of hardcoding a version. Opening a tab with `open_in_codex` alone does not prove automation access.
- Use Chrome or another browser only when the user asks for it or approves a necessary alternative, such as an existing external-browser login. If the in-app browser is unavailable or denies an action, distinguish connection failure, missing tools and permission denial, report the exact blocked step, and hand over the finished files for a manual step instead of retrying. Do not silently launch Chrome, switch automation backends, use raw CDP or weaken approval settings to bypass a denial. This preference selects a browser; it grants no permissions.
- Pre-flight for web apps that need state (Overleaf, Figma, Google, portals): confirm login, local fonts and file-URL access before starting an edit; never change a deliverable's specification (fonts, sizes) to fit the automation browser.
- API-created subagent tasks do not inherit the browser context: create browser tasks from the GUI, or run them one at a time, and map work by the application's own numbering (slide numbers, not PDF pages).
- Logins that need a code from the user: open and verify the code field first, then ask, say how long the session stays valid, and submit the code as the next action; if the session expired, say so before the user sends one. Do not drive a browser password manager's autofill; it raises an OS prompt only the user can answer. Links inside question cards are not reliably clickable: when a question asks the user to review a file, open it with `open_in_codex` first and name where it opened.
